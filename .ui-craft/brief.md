# Project Brief

## 1. Product purpose

ローカルで動くソフトウェアファクトリー（examples/local-agent-loop）の run について、いまの状態、次に人がすべきこと、工程ごとの時間と費用を1画面で見せる。

## 2. Primary user

ファクトリーを回している開発者本人。別のターミナルで worker を動かしながら、ラップトップのブラウザ（localhost）で数分おきに様子を見る。利用者は1人で、画面を見る時間は短い。

## 3. Principles（上ほど優先）

1. **説明より次の一手。** 状態を細かく説明する前に、人の判断が要る run と、そこで打つべきコマンドを先に見せる。
2. **分からないものは、分からないと見せる。** 使用量や費用が不明なときは、0 や空欄で埋めずに「不明」と書く。
3. **UI は記録を映すだけ。** UI 独自の状態や計算は持たない。数字は CLI の `report` / `compare` と必ず一致させる。
4. **色は状態を表すためだけに使う。** 装飾の色は入れず、色が付くのは「人待ち」「失敗」「実行中」だけにする。
5. **迷ったら減らす。** 網羅するより、シンプルで便利なほうを選ぶ。

## 4. Success metric

ページを開いて10秒以内に、「いま動いている run がどの工程にいるか」と「人の手が要る run があるか」が分かる。終わった run の工程ごとの時間と費用を、CLI の report と同じ数字で比べられる。

## 5. Out of scope

- run の操作（approve、reject、retrigger）はしない。表示するのはコマンドまでで、実行は CLI で行う
- localhost の外への公開、ログイン、複数人での利用
- factory.json や入力ファイルの編集
- エージェントの出力のリアルタイム表示（ログのストリーミング）
- 独自のグラフ表現。時間の比較には工程ごとの横棒だけを使う
