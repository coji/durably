# Dependency updates — September 2026

## Runtime and maintenance

Development uses Node.js **24.21.0** and pnpm **12.4.2**. `packageManager`, `engines`, and `devEngines.runtime` are declared in the root manifest; pnpm locks and downloads the runtime. Published core support now requires Node.js **22+**, matching better-sqlite3 13. Browser requirements remain secure context and OPFS support.

GitHub Actions use `pnpm/setup` with store caching and an explicit frozen install. The PostgreSQL test job uses its PostgreSQL 17 service instead of starting a second container. pnpm's native GitHub Actions updater pins actions to full commit SHAs with version comments:

```bash
pnpm deps:outdated
pnpm deps:update:actions
```

`update.githubActions` is enabled in `pnpm-workspace.yaml`. Keep the default minimum release age and verify every dependency update before accepting it. See [ADR-0002](adr/0002-development-toolchain.md) for the runtime, TypeScript API, and adapter decisions.

## Compatibility notes

TypeScript 7 supplies native `tsc` but no compiler API. The [official TypeScript 7 announcement](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/) documents keeping the compatibility compiler alongside it. Avoid changing the `typescript` alias to v7 until declaration bundling, import organization, and framework tooling support it.

The latest libSQL dialect still depends on client 0.8. The [database guide](../website/guide/databases.md#libsql--turso) describes the targeted pnpm override used here. This override is a workspace setting, not a transitive constraint published to consumers.

React Router 8 migration: [official upgrade guide](https://reactrouter.com/upgrading/v8). Vercel remains on 7 because its adapter has explicit v7 peers.

This is a recorded limitation, not a clean audit. Upgrade when VitePress publishes a compatible stable dependency set.

## SSE compatibility fix

Live browser checks exposed compressed SSE buffering in the fullstack example: the database run had completed while the UI still displayed pending. Add `Cache-Control: no-cache, no-transform` to SSE responses so compression middleware forwards events immediately. This follows the [compression middleware guidance](https://github.com/expressjs/compression#server-sent-events).

A real HTTP regression test requests gzip through `compression({ threshold: 0 })` and reads the first SSE event while the stream remains open. It times out before the fix and passes afterward. The test adds development-only `compression@^1.8.2` and `@types/compression@^1.8.1`; compression's 1.8.2 security fix was reviewed and also refreshed for framework servers. Existing SSE header assertions and both package docs/API reference are updated. No event payload or job execution API changed.
